# TinyBench.Sdk.RestHost

`TinyBench.Sdk.RestHost` is the service wrapper for a compiled TinyBench driver DLL.

It loads:

- a driver assembly containing one `[TinyDriver]` class
- the driver's `.tinybench` folder generated by `TinyBench.Sdk.Tools`

Then it exposes the driver through a small REST API.

Swagger is available at `/swagger`.

## Run

```powershell
dotnet run --project .\TinyBench.Sdk.RestHost\TinyBench.Sdk.RestHost.csproj -- `
  --driver-assembly .\TinyBench.Sdk.DemoDriver\bin\Debug\net10.0\TinyBench.Sdk.DemoDriver.dll `
  --docs .\TinyBench.Sdk.DemoDriver\.tinybench
```

## API Shape

- `GET /v1/definition`: full driver definition from `.tinybench`
- `GET /v1/device`: device metadata
- `GET /v1/connection`: connection parameter metadata
- `POST /v1/connection/connect`: invokes `[TinyConnect]`
- `POST /v1/connection/disconnect`: invokes `[TinyDisconnect]`
- `GET /v1/commands`: command metadata
- `GET /v1/commands/{commandId}`: one command definition
- `POST /v1/commands/{commandId}/runs`: starts a command run
- `GET /v1/runs`: run history
- `GET /v1/runs/{runId}`: one run
- `POST /v1/runs/{runId}/cancel`: requests cancellation

Command runs are serialized by default. If a command is already running, starting another command returns `409 Conflict`.

`TinyTable` inputs and outputs use a `columns` schema plus `rows` of scalar cells.
Columns declare `name`, `kind` (`String`, `Boolean`, `Integer`, or `Float`), and
`isNullable` (false by default). The host validates table inputs and shares the
`TinyBench.Core` assembly with loaded drivers. See the
[Core documentation](../TinyBench.Core/README.md) for a JSON example.

## Example

```powershell
Invoke-RestMethod -Method Post http://localhost:5000/v1/connection/connect `
  -ContentType 'application/json' `
  -Body '{"parameters":{"host":"localhost","port":1}}'

Invoke-RestMethod -Method Post http://localhost:5000/v1/commands/OpenDoor/runs `
  -ContentType 'application/json' `
  -Body '{"inputs":{}}'
```
